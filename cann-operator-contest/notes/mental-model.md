# CANN 算子开发心智模型

## 一句话理解

CANN 算子开发不是普通 C 程序开发，而是在写一个可以被昇腾 NPU 高效执行的小计算单元。

如果用以前的单片机经验类比：

- 单片机里要关心寄存器、外设、DMA、中断。
- CANN 算子里要关心 Tensor、内存层级、数据搬运、并行切分。

## Host 侧和 Device 侧

Host 侧更像“调度者”：

- 获取输入 shape 和 dtype。
- 计算 tiling 参数。
- 分配 workspace。
- 启动 kernel。

Device 侧更像“执行者”：

- 知道自己处理哪一段数据。
- 把数据从 GM 搬到 UB。
- 调用向量计算接口。
- 把结果从 UB 搬回 GM。

## 最常见的基础算子类型

### Element-wise

每个位置独立计算：

```text
y[i] = f(x[i])
z[i] = f(x1[i], x2[i])
```

典型例子：

- Add
- Sub
- Mul
- Div
- ReLU
- Abs
- AddCMul

这类题最适合入门，因为不需要复杂的数据依赖。

### Reduce

把一段数据聚合成更少的数据：

```text
y = sum(x)
y = max(x)
```

这类题会更难，因为要处理分块归约和跨 core 合并。

### MatMul

矩阵乘法：

```text
C = A * B
```

这类题通常涉及更多性能优化，不适合作为第一周主线。

## addcmul 的直觉

`addcmul` 一般可以先理解成：

```text
out[i] = input[i] + tensor1[i] * tensor2[i] * value
```

如果题目给出的公式不同，以题面为准。

它比 Add 多一步乘法，但本质仍然是 element-wise：

1. 每个 `i` 之间互不影响。
2. 可以把数组切成若干块。
3. 每个 core 独立处理自己那一块。
4. 最后把结果写回输出 Tensor。

## 入门时最容易卡的点

- 不知道哪些代码跑在 Host，哪些跑在 Device。
- 忘记处理最后一块不足 block 长度的尾数据。
- tiling 参数和 kernel 内读取参数不一致。
- 数据类型不匹配，例如 float16 和 float32 混用。
- 只看懂公式，但不知道输入输出在内存中怎么搬。

## 学习判断标准

真正掌握一道题，不是“看过题解”，而是能做到：

1. 盖住代码，自己说出公式和数据流。
2. 能说清 Host 侧为什么要算 tiling。
3. 能指出 Device 侧哪里搬数据、哪里计算、哪里写回。
4. 能改成同结构的另一个算子。
5. 能根据错误结果反推可能的问题。
