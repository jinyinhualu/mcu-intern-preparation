## 实际完成

- 确认工程中 LED 为 PA5，按键为 PB0。
- 读懂 PA5 的 HAL 配置：推挽输出、无上下拉、低速输出，初始输出低电平。
- 明白 `GPIO_MODE_OUTPUT_PP = 0x00000001u` 是 HAL 模式标记，不是直接写入 `CRL` 的四位值。
- 根据 `GPIO_SPEED_FREQ_LOW` 和推挽 CNF 推出 PA5 的实际字段为 `0010b = 0x2`，位置是 `GPIOA_CRL` bit 23:20。
- 读懂 `HAL_GPIO_WritePin(..., GPIO_PIN_RESET)` 最终写 `BSRR` 高 16 位，不会覆盖整个 `ODR`。
- 读懂 PB0 的 HAL 配置：下降沿外部中断、内部上拉。
- 根据 PB0 属于 0 号引脚，推出其实际 GPIO 字段为 `GPIOB_CRL` bit 3:0，配置值 `0x8`。
- 明白 `GPIO_PULLUP` 通过 `BSRR` 设置 `ODR0=1`，再配合 `CNF=10、MODE=00` 选择输入上拉。
- 拆解 `GPIO_MODE_IT_FALLING = 0x10210000u`：外部中断模式、下降沿触发、中断模式；该组合值不会原样写入 `CRL`。
- 理解 HAL 还会配置 AFIO 的 EXTI 映射、`EXTI_FTSR`、`EXTI_IMR`，并通过 `HAL_NVIC_SetPriority()` 与 `HAL_NVIC_EnableIRQ()` 配置 NVIC。
- 确认 PB0 松开时 `IDR0=1`，按下接地时 `IDR0=0`。
- 区分了硬件触发机制和用户回调：`HAL_GPIO_EXTI_Callback()` 只是中断发生后的应用响应函数，不决定下降沿或 NVIC 通道。
- 理解 HAL `HAL_GPIO_ReadPin()` 本质上检查 `GPIOx->IDR & GPIO_Pin`。

## 关键映射

### PA5

```text
HAL_GPIO_WritePin(..., GPIO_PIN_RESET)
→ GPIOA->BSRR = GPIO_PIN_5 << 16

GPIO_MODE_OUTPUT_PP + GPIO_SPEED_FREQ_LOW
→ GPIOA_CRL bit 23:20 = 0x2
```

### PB0

```text
GPIO_MODE_IT_FALLING + GPIO_PULLUP
→ GPIOB_CRL bit 3:0 = 0x8
→ ODR0 = 1
→ EXTI0 下降沿触发
→ EXTI0 中断屏蔽打开
→ NVIC 允许 EXTI0_IRQn
```

### 按键中断链路

```text
PB0 从高变低
→ EXTI0 检测下降沿
→ EXTI 挂起位 PR0 置位
→ EXTI0_IRQHandler
→ HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_0)
→ HAL 清除挂起标志
→ HAL_GPIO_EXTI_Callback(GPIO_PIN_0)
```

## 2. 中断、NVIC、优先级与按键消抖

### 手册定位

本轮继续使用 `mcu-32/STM32F10xxx参考手册（中文）.pdf`：

- 第 126～127 页：`AFIO_EXTICR1` 选择 `EXTI0` 的 GPIO 来源；`0001` 表示 `PB0`。
- 第 130 页：NVIC 有 68 个可屏蔽中断通道、16 个可编程优先等级，使用 4 位优先级。
- 第 131～133 页：向量表；普通 STM32F10xxx 中 `EXTI0` 是 IRQ 号 6，向量表位置 13，地址 `0x58`。
- 第 134～140 页：EXTI 的屏蔽、边沿触发和挂起寄存器；`EXTI_PR` 对应位写 1 清除挂起。
- 第 137 页：GPIO 到 EXTI 线的映射，配置 `AFIO_EXTICR` 前要打开 AFIO 时钟。

### 独立推导出的 PB0 中断链路

```text
PB0 输入上拉
→ AFIO_EXTICR1 选择 PB0 为 EXTI0
→ EXTI_RTSR/FTSR 选择边沿
→ EXTI_IMR bit0 打开请求
→ EXTI_PR bit0 挂起
→ NVIC 接收 EXTI0_IRQn
→ EXTI0_IRQHandler
→ HAL 清除挂起位并调用 HAL_GPIO_EXTI_Callback
```

区分了向量表位置和运行时优先级：位置 13 是固定的向量表条目，不是“优先级 13”。本例用 `NVIC_PRIORITYGROUP_4`，把 4 位全部用作抢占优先级，按键设为 7；优先级数值越小越紧急。

### 已实现的按键程序

新增 [mcu-32/2-EXTI/README.md](../mcu-32/2-EXTI/README.md) 和 [mcu-32/2-EXTI/key_exti_debounce.c](../mcu-32/2-EXTI/key_exti_debounce.c)，以 `PB0` 按键和 `PA5` LED 为例：

- GPIO 配置为输入上拉，EXTI 配置为双边沿，便于在软件中确认按下和释放的稳定状态。
- `HAL_GPIO_EXTI_Callback()` 只记录 `HAL_GetTick()`、置 `pending` 标志；没有 `HAL_Delay`、`printf`、串口发送或 LED 操作。
- `KeyDebounce_Task()` 在 `while (1)` 中调用，等待 20 ms 后重新采样 PB0，只在稳定状态由松开变为按下时切换 LED。
- 主循环复制共享标志时只短暂关中断；消抖等待和应用处理都在普通上下文中完成。
- 用无符号减法判断时间间隔，处理 `HAL_GetTick()` 回绕。
### 交互推导与竞态理解

- 区分了三个容易混淆的编号：`EXTI0` 的向量表位置是 13，IRQ 编号是 6，运行时优先级则由 NVIC 单独配置；位置 13 不是优先级 13。
- 明确了 `EXTI_PR` 是外设侧的挂起状态，`EXTI_IMR` 决定请求是否送往 NVIC，`NVIC_EnableIRQ()` 决定 NVIC 通道是否允许 CPU 响应，优先级数字越小越紧急。
- 理解了“硬件中断次数”和“应用按键事件次数”的区别：一次机械按键可能触发多次边沿，但消抖后只产生一次稳定的按下事件。
- 推导了 `key_last_edge_tick` 记录最近一次边沿、`key_debounce_pending` 作为待处理标志、`key_stable_state` 记录上一次稳定电平的职责分工。
- 理解了 `volatile` 只能保证每次访问真实内存，不能保证“读取、判断、清除”这组操作不可被中断插入；因此需要短临界区和时间戳复查来避免丢事件。
- 明白了按下和释放的区别：`RESET → SET` 只更新稳定状态，不产生按下业务；只有 `SET → RESET` 才产生一次按下事件。
- 明白了 `HAL_Delay()` 不能放在 EXTI 回调或关中断临界区中，否则会阻塞其他中断；若 SysTick 无法运行，延时还可能无法结束。

## 4. USART 状态位、接收溢出与环形缓冲区

### 实际完成

- 区分 `TXE` 和 `TC`：`TXE=1` 只表示发送数据寄存器可以接收下一个字节；`TC=1` 才表示最后一帧连停止位都发送完成。
- 理解 `RXNE`：接收完成后 `USART_DR` 有数据，软件应及时读取 `DR`。
- 理解 `ORE`：`RXNE` 尚未清零时下一个字节到达，旧数据仍在 `DR` 中，新字节可能丢失；`ORE` 表明至少发生过数据丢失。
- 能区分硬件接收溢出和软件环形缓冲区满：中断及时读取 `DR` 时，主循环慢主要会导致软件缓冲区满；全局中断关闭时，环形缓冲区没有机会接收数据，硬件可能在约一个字节时间后产生 `ORE`。
- 理解接收中断的三层链路：`USART_CR1.RXNEIE` 产生请求、NVIC 允许对应 IRQ、IRQ Handler 读取 `SR/DR` 并把字节放入环形缓冲区。
- 按 `115200 baud、8N1` 估算一个字节约 `86.8 us`，64 字节软件缓冲区约能覆盖 `5.56 ms` 的主循环处理延迟，前提是中断持续运行。
