## 本次纠正的关键概念

### 1. 索引加一不是地址加四

`head` 和 `tail` 保存的是数组下标，下一个位置应当加 `1`，不需要根据数据类型手动加字节数。即使数组元素不是 `uint8_t`，使用数组下标时，编译器也会根据元素类型计算实际地址。

只写 `tail++` 会在下标从 `7` 变成 `8` 后越过数组边界，因此还需要在到达容量时回到 `0`。`next_index()` 不是唯一写法，也可以使用取模或在读写函数内直接判断，但独立函数能够复用并集中管理回绕规则。

### 2. `pop` 是队列读出，不是栈操作

`ring_buffer_pop()` 读取并移除最早写入且尚未读取的元素，因此实现的是先进先出队列，不是后进先出的栈。

本工程中的命名约定是：

```text
head -> 下一次写入位置
tail -> 下一次读取位置
```

不同资料可能使用不同命名，判断时应看索引在实际代码中的用途。

### 3. `count == 0` 不等于数组内容全部为零

`ring_buffer_init()` 只把 `head`、`tail` 和 `count` 复位，没有清空 `data` 数组。`count == 0` 表示当前没有逻辑上的有效数据，即使数组内存里还残留旧字节，也不能通过 `pop` 读取。

### 4. `head == tail` 不能独立区分空和满

初始化时 `head == tail` 表示空；写满一整圈后，两个索引也可能再次相等，但此时表示满。因此当前实现使用：

```text
count == 0                     -> 空
count == RING_BUFFER_CAPACITY  -> 满
```

不能把 C 语言条件写成 `head == tail == 0`，因为它会被解释为 `(head == tail) == 0`，不是数学中的连续等式。

### 5. 环形缓冲区和 UART 起始位、停止位不是同一概念

UART 的起始位、数据位、校验位和停止位属于通信帧格式；`head`、`tail` 和 `count` 属于软件缓冲区的存储管理。串口接收可以使用环形缓冲区保存收到的字节，但这两层的职责不能混在一起。

### 6. 中断并发问题不只是优先级问题

如果中断负责写入、主循环负责读取，还需要分析共享索引和计数器是否会发生竞态、操作是否原子、更新顺序是否可靠，以及是否需要临界区或单生产者单消费者约束。`volatile` 只能约束编译器访问，不能自动提供原子性或并发安全。

## 当前掌握情况

### 已经理解

- 环形缓冲区使用固定数组重复利用存储空间，不需要在每次读取后移动全部数据。
- `push` 在 `head` 位置写入，`pop` 在 `tail` 位置读取，成功操作后推进对应索引。
- `count` 表示有效元素数量，并解决 `head == tail` 无法区分空和满的问题。
- 满时拒绝写入可以保护尚未处理的历史数据，但覆盖最旧数据也是另一种可设计的策略。
- 测试全部通过只证明当前断言覆盖的行为，不代表模块已经自动具备中断并发安全性。

### 仍需巩固

- 不看源码独立写出一个固定长度环形缓冲区。
- 手工推演多次写入和读出后 `head`、`tail`、`count` 的变化。
- 在 STM32 串口接收中正确划分 ISR、主循环和环形缓冲区的职责。
- 分析中断与主循环共享状态时的原子性、临界区和数据可见性。
- 根据实际业务选择“满时拒绝新数据”还是“覆盖最旧数据”，并为策略补充测试。
