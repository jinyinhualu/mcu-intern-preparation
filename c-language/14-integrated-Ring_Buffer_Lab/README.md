# 14-integrated-Ring_Buffer_Lab

## 场景

模拟单片机串口接收缓冲区：中断或 DMA 把字节写入固定长度数组，主循环按先进先出顺序取出字节。缓冲区满时本练习选择“拒绝新数据”，不覆盖还没有处理的旧数据。

## 接口与不变量

- 容量固定为 `RING_BUFFER_CAPACITY == 8`。
- `head` 指向下一次写入位置，`tail` 指向下一次读出位置。
- `count` 表示当前有效字节数，范围始终是 `0..RING_BUFFER_CAPACITY`。
- 写入或读出到数组末尾后，索引回到 `0`。
- `push` 成功后 `count` 加一，`pop` 成功后 `count` 减一。
- 空缓冲区不能读，满缓冲区不能写。

## 编译运行

```powershell
gcc -Wall -Wextra -std=c11 main.c ring_buffer.c -o ring_buffer_lab.exe
.\ring_buffer_lab.exe
```

## 测试覆盖

1. 初始化后的空状态和容量状态。
2. 空缓冲区读取失败。
3. `NULL` 缓冲区、`NULL` 输出指针的异常路径。
4. 正好写满 8 个字节。
5. 满缓冲区拒绝第 9 个字节，确认没有覆盖旧数据。
6. 连续读出验证 FIFO 顺序。
7. 读出一部分后继续写入，验证 `head/tail` 回绕。
8. 回绕后再次验证旧数据和新数据的整体顺序。

## 逐段解释

- `next_index()` 只负责一个位置的回绕，避免在读写函数里重复边界表达式。
- `ring_buffer_push()` 先检查空指针和满状态，再写 `head`，推进 `head`，最后增加 `count`。
- `ring_buffer_pop()` 先检查空指针、输出指针和空状态，再从 `tail` 取值，推进 `tail`，最后减少 `count`。
- 同时保存 `head`、`tail` 和 `count`，可以区分“空”和“满”时 `head == tail` 的情况；只保存两个索引时还需要额外保留一个空槽或增加状态位。
- 当前模块适合单线程或由上层保证并发安全的场景。若中断和主循环同时访问，还要考虑临界区、原子性和 `volatile` 的边界，不能仅靠这个数据结构自动解决竞态。

## AI 使用记录

- 先列出两个风险假设：一是只用 `head == tail` 可能无法区分空和满；二是回绕时可能越过数组边界或破坏 FIFO 顺序。
- 验证方法：用“写满后第 9 次写入”和“读出 3 个后再写 6 个”的测试分别验证容量边界与索引回绕。
- 采用实现后，至少运行一条正常路径（FIFO 写入/读出）和一条异常路径（空读、满写、`NULL` 参数）。
