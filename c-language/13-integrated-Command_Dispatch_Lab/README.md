# 13-integrated-Command_Dispatch_Lab

## 综合题：电脑端冷链终端命令分发表

这次先不接 STM32。你要在电脑端写一个简化的命令行分发模块，模拟上位机通过串口或网络收到文本命令后，找到对应处理函数并执行。

目标命令示例：

```text
led on
led off
add 5
status
```

核心数据流：

```text
命令文本 -> 拆分参数 -> 查找命令表 -> 调用函数指针 -> 更新上下文 -> 通过回调记录结果
```

## 本题要完成的任务

### 任务 1：完成 `command_split_line()`

要求：

- 按空白字符拆分一行命令；可以使用 `strtok`，但要理解它会修改输入缓冲区。
- 返回参数个数，并把每个参数首地址写入 `argv`。
- 跳过连续空格、制表符和换行符。
- 空行返回 `0`。
- 参数数量超过 `argv_capacity` 时返回 `0`，不要写越界。

### 任务 2：完成 `command_find()`

要求：

- 在线性命令表中查找名字完全相同的命令。
- 找到时返回对应表项地址，找不到时返回 `NULL`。
- 不要修改命令表内容。

### 任务 3：完成 `command_dispatch()`

要求按顺序实现：

1. 检查输入指针、命令表指针和上下文指针。
2. 调用 `command_split_line()`。
3. 空行返回 `COMMAND_EMPTY`。
4. 用第一个参数查找命令。
5. 找不到命令时增加 `ctx->error_count`，发出一次回调日志，返回 `COMMAND_UNKNOWN`。
6. 找到命令后调用表项中的 `handler` 函数指针。
7. 每次真正进入一个处理函数时，增加 `ctx->dispatch_count`。
8. 将处理结果通过回调通知上层，但不要让“没有注册回调”导致程序崩溃。

注意：处理函数收到的 `argc/argv` 应该只包含完整命令参数，例如输入 `led on` 时，处理函数收到的仍然是 `argc == 2`、`argv[0] == "led"`、`argv[1] == "on"`。

### 任务 4：完成 `command_set_log_callback()`

要求：

- 保存回调函数指针和 `user_data`。
- 允许传入 `NULL` 清除回调。
- `user_data` 不要强转成全局变量，必须原样保存并在回调时传回。

### 任务 5：逐段解释

完成后，至少能解释：

1. `CommandHandler` 为什么是函数指针类型，而不是普通函数声明。
2. `CommandEntry.handler` 保存的是什么，`table[i].handler(...)` 实际调用了谁。
3. 回调和普通函数调用的方向有什么不同：谁注册，谁触发，谁实现具体动作。
4. 为什么命令表和处理函数参数使用 `const`。
5. 为什么 `user_data` 要跟回调函数指针一起保存。
6. 为什么 `command_split_line()` 会要求调用者提供可写的 `line` 缓冲区。
7. 函数指针能解决“根据字符串选择函数”，但不能自动解决参数校验和并发安全问题。

## 建议验证顺序

1. 先只完成字符串拆分，验证空命令、连续空格和参数数量上限。
2. 再完成命令查找，验证命令存在和不存在两条路径。
3. 再完成函数指针调用，先跑 `led on` 和 `add 5`。
4. 最后接入回调，验证注册回调、清除回调、未知命令和参数错误。
5. 增加一个“命令处理函数返回错误，但分发器仍然继续工作”的测试，区分返回值与分发次数。
