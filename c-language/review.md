## 1. 指针、数组与参数传递

已答对或在后续小题中答对：

- `swap(int a, int b)` 修改副本；传入对象地址后，可以通过解引用修改调用者对象。
- `a[2]`、`*(p + 2)`、`p[2]` 在 `p = a` 时访问同一个元素。
- 二维数组 `int a[2][3]` 在普通表达式中转换为 `int (*)[3]`，`a + 1` 跳过一行。
- `int *p = &x; int **pp = &p;` 中，`p` 保存 `x` 的地址，`pp` 保存 `p` 的地址。
- 后续能判断通过 `int *` 修改整数，以及通过 `int **` 改变调用者指针的指向。

暴露的问题与纠正：

- 曾把 `&a` 说成“首元素地址的地址”。对 `int a[5]`，`&a` 是整个数组的地址，类型为 `int (*)[5]`，并非 `int **`。
- `a` 本身是数组；在多数表达式中转换为首元素指针。对数组直接使用 `sizeof` 或取地址时不能套用普通退化结论。
- 曾把 `sizeof(a)` 答成 21、`sizeof(p)` 答成 4。若 `int` 为 4 字节，则五元素数组占 20 字节；指针大小由目标平台决定，不能由 `int` 大小推出。
- 函数形参 `int a[5]` 会调整为 `int *a`，函数内部 `sizeof(a)` 得到指针大小，需要另传长度。
- 曾认为 `**pp = 20` 会改变指针地址。实际上它修改 `x`；`*pp = ...` 才修改 `p`。

## 2. const 与字符串

已答对：

- `const int *p` 可以改指向，不能通过它修改整数；`int *const p` 可以修改目标整数，不能改指向；双重 `const` 两者都限制。
- 字符数组可逐字符修改；`char *p = a` 只复制地址，不复制字符串。
- 后续能判断数组不能整体赋值，以及使用 `strcpy` 复制字符串。

暴露的问题与纠正：

- `char a[] = "hello"` 的 `sizeof(a)` 为 6，`strlen(a)` 为 5；终止字符占空间，但不计入字符串长度。
- 在 C 中，`char text[5] = "hello"` 可以初始化，但没有空间保存结尾的 `\0`，不能作为普通以零结尾的字符串交给 `strlen` 或无限定精度的 `%s`。
- `printf("%5s", text)` 中的 5 是最小输出宽度，不是最多读取字符数；与 `scanf("%5s", buffer)` 的输入宽度含义不同。
- `scanf("%5s", buffer)` 要求目标至少有 6 字节；仍需检查输入返回值。
- `strcpy(buffer, "hello")` 会复制 6 字节，容量为 5 时越界。
- `const` 指针限制访问途径；修改真正定义为 `const` 的对象属于未定义行为。

## 3. 结构体、联合体、枚举与对齐

已答对：

- 结构体可以整体赋值；内嵌字符数组会随结构体复制，修改副本中的数组不影响原对象。
- `p->id` 与 `(*p).id` 等价。
- 联合体大小不是成员大小之和；不能随意调整具有固定布局约束的寄存器结构。
- 在大小和对齐分别为 1、4、2 的题设下，`char/int/short` 结构体大小为 12。

暴露的问题与纠正：

- 传结构体得到副本，传结构体指针得到地址的副本，可通过它访问原对象；结构体中的指针成员整体复制后仍可能指向同一对象。
- 曾认为联合体写入 `f` 后，`i` 仍可靠地保持 100。联合体成员共享存储，写入一个成员会覆盖重叠字节，不独立保存每个成员的值。
- 枚举类型标签用于记录联合体当前哪个成员有效；标签与数据需要程序保持一致，联合体不会自动记录。
- `int/short/char` 成员共 7 字节，但在题设对齐下结构体占 8 字节，最后有 1 字节尾部填充。
- 每个成员按自己的对齐要求安排偏移，整体再补齐；不是后一个成员一律适应前一个成员。
- 大小为 8 的结构体数组从 `0x1000` 开始，第二个元素在 `0x1008`，不是 `0x10000`。
- 实际布局需要通过 `sizeof`、`offsetof` 等验证，不能把题设大小当作所有平台的保证。

## 4. 存储期、动态内存与跨文件关键字

已答对：

- 局部 `static` 的名字不能在函数外直接使用。
- 能区分 `extern` 声明与对象定义；`typedef` 不改变布局或大小。
- 知道局部对象生命周期结束后，不能再通过保留的地址访问它。

暴露的问题与纠正：

- 普通局部变量每次进入重新初始化；局部 `static` 跨调用保留。计数示例三次输出为 `1 1`、`1 2`、`1 3`。
- 未显式初始化的普通局部变量不保证为零；静态存储期对象会零初始化。
- 文件作用域 `static` 赋予内部链接，其他文件写 `extern` 不能访问同一个私有对象。
- `int count = 0;` 是定义并初始化；带初始化的 `extern int count = 0;` 也是定义。
- `int *q = p; free(p); p = NULL;` 后，`q` 不会自动清空，不能继续解引用；原因是目标内存已释放，不是“内存分区不同”。
- 作用域回答名字在哪里可见，存储期回答对象何时存在，链接属性回答不同声明是否指向同一实体。

## 5. 位运算、宏与 volatile

已答对：

- `0x0A | (1u << 0)` 得到 `0x0B`；清除 bit3 使用 `reg &= ~(1u << 3)`。
- 能初步区分按位与 `&` 和逻辑与 `&&`。
- 知道仅用 OR 不能可靠地把旧字段 7 改成 2。
- 原宏 `#define SQUARE(x) x * x` 对 `SQUARE(1 + 2)` 的展开结果为 5。
- 带副作用的宏实参应避免重复求值。

暴露的问题与纠正：

- `(reg & mask) >> pos` 中，掩码先排除其他位，再右移得到字段普通数值；右移不是代替掩码。
- 写字段用 `(reg & ~mask) | ((value << pos) & mask)`，先清旧位，再写新位并限制范围；同时确保类型及位移量合法。
- 宏需给参数和整体表达式加括号：`#define SQUARE(x) ((x) * (x))`。例如只加参数括号时，`18 / SQUARE(3)` 会变成 `18 / 3 * 3`。
- 即使括号齐全，`SQUARE(i++)` 仍不安全；括号不会消除重复求值和未排序修改的问题。
- 多次误认为 `volatile` 能避免并发计数丢失。它约束编译器对访问的处理，不保证原子性、互斥或线程安全，也不会自动禁止中断。
- `volatile` 不是获得硬件修改权限的开关。寄存器可能被硬件异步改变，需要按目标平台规则保留必要访问。

## 6. 函数指针与回调：已恢复重点复习

已答对：

- `typedef int (*Handler)(int);` 定义函数指针类型；保存 `double_value` 后调用 `handler(5)` 得到 10。
- 最小回调例子中，能判断通过传入的整数地址使计数从 0 变为 1。
- 知道保存普通局部对象地址后，不能在对象生命周期结束后再安全访问。

前期暴露的问题与纠正：

- 函数名表示函数，在相应表达式中转换为函数指针；指针变量保存该函数地址。
- 注册回调通常保存“调用哪个函数”和“传回哪个数据对象地址”，不是函数指针发挥作用的必经步骤。
- 函数指针可以直接调用、作为参数传入、存入命令表；回调也不一定异步执行。
- `void *user_data` 是通用对象指针参数，与“函数可以返回任何类型”无关；回调签名仍然固定。
- `int *count = user_data;` 只建立指向关系，下一句 `(*count)++` 才修改整数。
- 调用 `NULL` 函数指针属于未定义行为；空指针不是一个可调用的函数，也不能仅理解为数据变得不可预测。

## 7. 环形缓冲区

约定：容量 8，`head` 为下一次写入位置，`tail` 为下一次读取位置，`count` 为有效元素数量；满时拒绝新数据。

| 操作后 | head | tail | count | 读出值 |
| --- | --- | --- | --- | --- |
| 初始化 | 0 | 0 | 0 | 无 |
| 写入 10、20、30 | 3 | 0 | 3 | 无 |
| 再读出一次 | 3 | 1 | 2 | 10 |

已答对：

- 索引到末尾后要回到 0；有效数量为零不意味着数组内容全部为零，初始化不必清空全部数据。
- 后续能算出 `(7, 3, 4)` 连续成功写入两次后变为 `(1, 3, 6)`。
- 空读失败不应推进 `tail` 或减少 `count`。

暴露的问题与纠正：

- 最初混淆读写索引，读出时还曾返回 0，而不是 FIFO 中最早写入的 10。
- 两次读出后仍把 `count` 保持为 4；正确的 `(6, 2, 4)` 读两次结果为 `(6, 4, 2)`。减少有效数量仍需复测。
- 满时拒绝写入必须保持索引、数量和旧数据不变。
- `pop` 返回值表示读出是否成功，输出指针接收读出的字节；不是写入结果。
- `head++` 从 7 到 8 本身不是整数溢出，后续访问 `data[8]` 才越界。
- `head == tail` 在当前方案中可能为空或满；`head == tail == 0` 不是数学连续等式。

## 8. 边界检查与验证

已答对：

- 含两端的合法温度范围使用 `>=` 和 `<=`。
- 累计非法样本数不能因正常样本到来而清零。
- 只检查返回值不能证明计数器和状态位正确。
- 编译无警告、已有测试通过不等于没有错误；越界可能没有可见日志。

需巩固：

- 使用 `data[0]` 前检查 `data != NULL` 和 `length > 0`。本题漏答，已讲解，尚未回测；调用者还须保证实际有效容量足够。
- 测试描述应明确“初始条件、操作、期望结果”，不能只写“计数不越界检测”。
- 环形缓冲区应覆盖空读、满写、空指针、回绕后的 FIFO 顺序，并验证失败时状态和旧数据不变。
- 未定义行为可能崩溃、破坏数据或暂时无异常，不能由一次输出推断其安全性。
