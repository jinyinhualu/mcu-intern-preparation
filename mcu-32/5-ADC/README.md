# ADC 与 DMA：从采样功能到数据搬运

整理日期：2026-10-09。学习背景为 STM32F103；本页归纳此前概览和本次问答，不把材料出现过或答对过一次等同于独立实现通过。

## 1. 先从熟悉的 ADC 采样看系统分工

ADC 把模拟电压变成数字，DMA 把数据从一个地址搬到另一个地址，CPU 负责解释数据和作出决定。定时器可以提供稳定采样节拍，也可以输出 PWM。

```text
软件 / 定时器触发
       ↓
传感器电压 → ADC 采样、转换 → ADC_DR → DMA → SRAM 数组
                                             ↓
                                     CPU 换算、滤波、判断
```

以温控风扇为例，功能链是“定期测温 → 换算温度 → 决定转速 → 输出 PWM”。低频测温可以先用单次 ADC，连续大量采集才考虑 DMA，要求采样节拍稳定时再引入定时器触发。DMA 不测量电压，不计算温度，也不主动让 ADC 再采一次。

用户已有 ADC 采样、PWM 和定时器中断的基本使用经验；后续先从这些功能入手，再解释实现细节，最后对应寄存器。

## 3. ADC 测得的数字与时间

STM32F103 ADC 为 12 位，共 4096 个编码，结果范围 0～4095。以参考范围 0～3.3 V 为例，理想量化步长约为 `3300 / 4096 = 0.806 mV`。常用端点换算是 `raw × Vref / 4095`；它与量化步长的分母用途不同。换算应使用真实参考电压，12 位分辨率不代表实际准确度必然达到 12 位。

PA0/PA1/PA2 分别对应本例的 ADC 输入通道 0/1/2，GPIO 使用模拟输入。多个输入通道共用 ADC 转换器，扫描通常依次转换，不是同时取得全部电压。

```text
总转换时间 = (采样周期数 + 12.5) / ADCCLK
PCLK2 = 72 MHz，六分频 → ADCCLK = 12 MHz
55.5 周期采样 → 一次转换约 5.67 μs
```

STM32F103x8/xB 的 ADC 时钟最大为 14 MHz；不能把 72 MHz 直接作为 ADC 时钟，也不能四分频为 18 MHz。输入源阻抗较高时，内部采样电容充电较慢，采样时间不能一味选最短。ADC 时钟、一次采样所用时间、每秒实际取得的样本数量是不同概念。

规则组最多 16 次转换，顺序由 SQR 配置，共用 DR；注入组最多 4 次转换，结果放在 JDR1～4，可用于需要特定采样时机的应用。本轮主要讨论规则组，复杂注入和双 ADC 应用未做实现验收。

## 4. 怎样产生结果，怎样搬运结果

| 控制 | 回答的问题 |
| --- | --- |
| ADC SCAN | 一轮是否按配置序列转换多个通道 |
| ADC CONT | 一轮结束后是否自动再来一轮 |
| ADC 触发选择 | 何时开始一轮转换 |
| ADC DMA 请求使能 | 结果出现时是否请求 DMA 搬运 |
| DMA MINC | 每次搬运后是否移动内存写入地址 |
| DMA CNDTR | 还需搬运多少个数据项 |
| DMA CIRC | 搬完规定数量后是否重装计数和内部地址 |

在本轮外设请求模式中，一次单通道转换产生一次搬运请求；DMA 循环并不会重复读取唯一一次转换的旧结果。扫描一轮包含多个转换，因此一次触发可以带来多个数据项。

### 单通道、地址不递增

条件：CONT=0，MINC=0，CIRC=1，初始 CNDTR=4，数组全零。两次软件触发依次得到 100、200：

| 时刻 | 数组 | 剩余计数 |
| --- | --- | ---: |
| 初始 | `{0, 0, 0, 0}` | 4 |
| 第一次搬运后 | `{100, 0, 0, 0}` | 3 |
| 第二次搬运后 | `{200, 0, 0, 0}` | 2 |

之后无新触发，DMA 等待；通道开启不等于正在搬运。MINC=0 只让结果覆盖同一位置，计数仍递减，普通模式达到零后停止搬运。

### 两通道扫描、地址递增

条件：扫描顺序通道 2 → 通道 0，CONT=0，MINC=1，CIRC=1，初始 CNDTR=4。两次触发分别得到 `(100,300)` 与 `(200,400)`：

```text
第一次搬运后：{100,300,0,0}，CNDTR=2
第二次搬运后：{100,300,200,400}，CNDTR 重装为 4
第三次触发后才开始覆盖数组开头
```

通道 1 不在序列内，不会因为编号位于 2 与 0 之间就被转换。序列可以任意配置，DMA 根据到来的顺序放入数组。

## 5. 数据宽度、地址和数组空间

对 `uint16_t samples[12]`，正确匹配为 PSIZE=16 位、MSIZE=16 位、CNDTR=12，共搬运 24 字节。地址配置用 `&ADC1->DR` 与 `samples`（等价于 `&samples[0]`），传入地址而非当前值。把地址转为 uint32_t 不决定传输宽度。

如果错把 MSIZE 设为 32 位，仍保持 PSIZE=16 位、MINC=1、CNDTR=12：

- 每次读取 2 字节，补零后写入 4 字节；目标地址每次加 4 字节。
- 两个 uint16_t 元素位置会被一次 32 位写入占用，例如 `{100,0,200,0,...}`。
- 12 次写入需要 48 字节，原数组只有 24 字节，第 7 次就越界。
- 第 7 次搬完后 CNDTR 仍为 5；DMA 不认识 C 数组边界。目标仍是可访问 SRAM 时，越界不一定触发 TE。

因此匹配“数组元素类型 ↔ MSIZE，数组元素数量 ↔ CNDTR，数组布局 ↔ MINC”。不要把地址步长说成“加 32 位”，此处是“加 4 字节”。

## 6. 固定采样节拍与处理期限

定时器每 1 ms 触发一轮三通道扫描，CONT=0，且整轮在下次触发前完成：

```text
每通道 1000 样本/秒
DMA 总计 3000 项/秒 = 6000 字节/秒
12 项缓冲区包含 4 轮，完整填满约 4 ms
每半块 6 项包含 2 轮，HT 到 TC 约 2 ms
HT 和 TC 各约 250 次/秒，两个通知合计约 500 次/秒
```

事件区间计算假设扫描用时及排列一致。定时触发会以一轮为单位产生一串数据，不应把它理解成各个数据项始终均匀间隔。

在连续循环搬运中，HT 后处理前半块、TC 后处理后半块，并在 DMA 再次写入该块前完成读取。示例：持续均匀搬运 6000 项/秒，12 项缓冲区每半块约 1 ms；若 CPU 直接处理前半块要 1.5 ms，就无法保证读到未被覆盖的完整旧块。

volatile 不锁住缓冲区，也不产生整块快照。可以先在期限内复制到空闲内存再计算，但还需处理副本容量和长期吞吐量；扩大缓冲区只能缓解短期延迟，不能解决持续处理速度不足。

## 7. 完成事件与中断通知

| 事件标志 | 中断使能 | 含义 |
| --- | --- | --- |
| HTIF | HTIE | 半块传输完成 |
| TCIF | TCIE | 配置数量传输完成 |
| TEIF | TEIE | 传输错误 |

事件发生会置标志；对应使能位允许发出中断请求；CPU 实际响应还取决于 NVIC、全局屏蔽和优先级等条件。

```text
TCIF=1、TCIE=0：有完成标志，无 TC 中断请求
TCIF 仍为 1，再打开 TCIE：已有标志就满足 TC 请求条件
先清 TCIF，再开 TCIE：旧事件不再引发 TC 请求
```

不要求硬件在完成瞬间“检查一次之后就错过事件”。TCIF 是保持的标志，不是完成次数计数器；不及时处理，多轮完成可能合并为一个标志。

读 ISR 检查状态，向 IFCR 对应清除位写 1 清标志。清 TCIF 不清数组，也不停止循环搬运。若 HTIF 和 TCIF 同时为 1，两个独立 if 可以在一次进入 IRQ Handler 时依次处理两者；if/else if 只执行一个分支，另一个标志仍可能保持并造成后续响应。

标志已同时挂起不保证两块旧数据都还有效。IRQ 延迟时仍须检查覆盖风险，不能凭事件计数就认定样本有效。

## 8. 最后对应到代码和寄存器

[adc_dma_learning.c](adc_dma_learning.c) 是本轮代码汇总，包含由助手整理的初始化与函数，不能记为用户已经独立写出完整驱动。

| 功能意图 | 本例对应代码或字段 |
| --- | --- |
| 选择 PA0 的电压 | PA0 模拟输入，SQR3 第一次转换选通道 0 |
| 给采样电容足够获取时间 | SMPR2，55.5 周期 |
| 打开并校准 ADC | ADON、稳定延时、RSTCAL、CAL |
| 单次取得一个值 | SWSTART → 等 EOC → 读 DR |
| 扫描 PA0/PA1/PA2 | SCAN，SQR1.L=2，SQR3 顺序 0/1/2 |
| 自动连续采样 | CONT=1 |
| 每个定时事件采一轮 | CONT=0，EXTSEL=100 选 TIM3_TRGO |
| 结果自动写入数组 | ADC DMA 请求 + DMA 通道 EN |
| 半字结果依次放入数组 | CPAR 固定，CMAR 递增，PSIZE/MSIZE=16 位 |
| 写满后回到开头 | CIRC，CNDTR=12 |
| 通知 CPU 哪半块完成 | HTIE/TCIE、NVIC、独立 if 检查 ISR 并写 IFCR |

使用路线示意：

```c
/* 低频单次读取；函数原型在工程中另行声明。 */
ADC1_InitPA0();
uint16_t raw = ADC1_ReadPA0();

/* 连续三通道采集；不要再并发调用单次读取。 */
ADC1_InitScan012();
ADC1_StartContinuousDMA();

/* 定时采集路线：与连续路线二选一。 */
ADC1_InitScan012();
ADC1_SelectTIM3TRGO();
ADC1_PrepareCircularDMA();
/* 在工程中另行配置 TIM3 的周期和 TRGO，再启动 TIM3。 */
```

三个片段是独立用法，不是建议在主函数里连续照抄执行。文件依赖 STM32F1 器件头、真实的 PCLK2=72 MHz 和 DelayUs()；需独占或合并相关 ADC、DMA、中断资源。默认沿用 stm32f10x.h；使用 STM32CubeF1 头文件时，定义 ADC_DMA_USE_CUBE_HEADERS 和 STM32F103xB，源文件内的名称适配保留本轮学过的 DMA 宏名称。
