## 1. 功能地图与资料

```text
STM32 主机内部
CPU：组织命令、控制 CS、读取状态、保存与解释数据
                       ↕ 外设总线访问
SPI：发送缓冲区、移位寄存器、接收缓冲区、时钟与控制电路
                       ↕ SCK / MOSI / MISO
外部传感器：按自身协议解析命令、接收配置、输出数据
```

| 信号 | 本例用途 |
| --- | --- |
| SCK | STM32 主机产生串行时钟 |
| MOSI | 主机输出，传感器输入 |
| MISO | 传感器输出，主机输入 |
| CS | 本例低有效，由 GPIO 选中传感器并界定一次操作 |

CS 是本例区分外部器件的依据，不把寄存器地址当成 I2C 式设备地址。SPI 也没有 I2C 那样统一的 START、STOP、ACK/NACK 阶段；具体命令与结束要求由器件手册决定。

## 2. 一个字节交换：同一组时钟，两个方向

在当前 8 位、全双工主机模式下，主机发送一个字节的同时，也采样一个字节。数据逐位在 MOSI/MISO 上传输，由 CPOL/CPHA 决定更新与采样边沿。

```text
同一组 8 个时钟周期
MOSI：主机输出 8 位
MISO：主机采样 8 位
```

主机想读数据时也要提供时钟，因此通常向 SPI 写入一个占位字节，如 `0x00`。它不是“即将通信”的通知，没有普遍适用的特殊含义；它是在读取期间实际输出的内容，能否任意取值须看器件协议。

写操作即使不使用 MISO 内容，全双工接收仍会发生，需要处理收到的数据以避免溢出。

## 3. DR、两个缓冲区与移位寄存器

```text
                       SPI 外设内部
CPU 写 DR → 发送缓冲区 → 移位寄存器 → MOSI
                            ↑ MISO
CPU 读 DR ← 接收缓冲区 ← 收齐一个字节
```

发送与接收缓冲区独立，均不是 C 数组；SPI 移位寄存器属于外设，也不是 CPU 通用寄存器。

同一个 DR 地址配合读写方向，访问不同缓冲区：

```c
SPI1->DR = tx;                 // 发送缓冲区
rx = (uint8_t)SPI1->DR;        // 接收缓冲区
```

DR 数据字段定义为 16 位。当前配置 8 位帧时，两个缓冲区各处理一个 8 位数据项，使用 DR 低 8 位；不应想成两个字节挤在同一个 8 位盒子里。

移位电路的逻辑作用是串并转换：发送字节整体装入后逐位输出，输入位逐渐收齐后整体交给接收缓冲区。图 209 将核心画为移位寄存器；按收发方向展开的数据路径是功能示意，不额外断言内部有两套独立物理移位寄存器。

## 4. 三个标志分别回答不同问题

| 标志 | 为 1 时的含义 | CPU 常见动作 |
| --- | --- | --- |
| TXE | 发送缓冲区空 | 可以写入下一字节 |
| RXNE | 接收缓冲区有完整未读数据 | 读取 DR |
| BSY | SPI 仍在进行传输 | 结束前需继续等其清零 |

- CPU 写 DR 后 TXE 清零；硬件把发送缓冲数据装入移位寄存器后 TXE 置一，不必等该字节发完。
- 接收字节收齐并存入接收缓冲区时 RXNE 置一；读 DR 清除 RXNE。
- RXNE 清零表示没有未读数据，不保证原存储位被擦成零。
- RXNE=1 已说明可以读到完整字节，无须为了数据有效性再等待 BSY=0。
- 连续收发时 BSY 可跨越多个字节保持为一；CS 保持低但字节间有空隙时，也可能 BSY=0。
- F103 SPI 这里使用 BSY；不要套用上一节 I2C 的 BTF 或 STOP 处理。

## 5. A/B/C 的连续数据路径

大写 A/B/C 表示发送字节，小写 a/b/c 表示对应时钟下收到的字节，内容不必相同。以下按事件排列，不代表事件之间一定留有可观测间隔。

| 事件 | 发送缓冲区 | 移位电路 | 接收缓冲区 | 主要变化 |
| --- | --- | --- | --- | --- |
| CPU 写 A | A | 等待开始 | 无未读数据 | TXE=0 |
| 硬件装入 A | 空 | A/a 交换中 | 无未读数据 | TXE=1，BSY=1 |
| CPU 提前写 B | B | A/a 交换中 | 无未读数据 | TXE=0 |
| a 收齐，B 接着处理 | 空 | B/b 交换中 | a | TXE=1，RXNE=1，BSY=1 |
| CPU 读 a | 空 | B/b 交换中 | 无未读数据 | RXNE=0，软件保存 a |
| CPU 提前写 C | C | B/b 交换中 | 无未读数据 | TXE=0 |
| b 收齐，C 接着处理 | 空 | C/c 交换中 | b | TXE=1，RXNE=1，BSY=1 |
| CPU 读 b | 空 | C/c 交换中 | 无未读数据 | RXNE=0 |
| c 收齐 | 空 | 最后一帧收尾 | c | RXNE=1；BSY 清零时机取决于时序 |
| 线路结束且 CPU 取走 c | 空 | 空闲 | 无未读数据 | TXE=1，RXNE=0，BSY=0 |

核心关系：CPU 可以准备下一字节、读取上一字节，SPI 硬件同时处理当前字节。下一字节已排队时，硬件不会等待 CPU 读取前一个接收字节才开始传输。

接收 c 与线路完全空闲要分别判断；CPU 可以先读 c 再等 BSY，或者在硬件已经空闲后才读取。它们不是同一个事件。

## 6. 溢出：硬件不会无限等 CPU

若 a 仍在接收缓冲区，b 又接收完成，F103 SPI 的结果是：

```text
接收缓冲区仍保留 a
b 丢失
OVR 置一
```

CPU 需在 b 接收完成前读走 a，为新字节腾出位置，并在工程中预留时序余量。若连续传输时坚持等 BSY=0 才读取，可能错过前面字节并溢出。

本轮只学习原因与结果。OVR 的清除、失败报告和后续恢复尚未独立实现，不将一次读 DR 等同于完整恢复。

## 7. 单字节交换与外层读写

示例假设 SPI 已初始化为 8 位主机全双工、开始时无遗留数据和错误。以下为教学轮询片段，缺少超时与错误返回，未编译验收。

```c
uint8_t SPI_Exchange8(uint8_t tx)
{
    while ((SPI1->SR & SPI_SR_TXE) == 0) {}
    SPI1->DR = tx;

    while ((SPI1->SR & SPI_SR_RXNE) == 0) {}
    return (uint8_t)SPI1->DR;
}
```

函数返回前已经读出接收数据。连续调用时，CPU 必须等第一次函数返回才能调用下一次，因此没有利用硬件提前排队的能力；普通低频寄存器读取可以使用这种简单结构，是否需要连续无空隙取决于协议和性能要求。

外层函数负责 CS 和整次操作：

```text
读取：CS 低 → 读取命令 → 占位交换并保存数据 → 确认结束 → CS 高
写入：CS 低 → 写入命令 → 实际数据交换       → 确认结束 → CS 高
```

结束前处理完最后接收数据，确认 TXE=1，再等待 BSY=0，满足器件 CS 保持时间后拉高 CS。数据是否有用不决定是否等待 BSY；结束动作和器件时序才是判断依据。

低有效 CS 拉高是取消选中。命令与数据之间随意拉高，可能结束当前协议状态；不能仅因每次字节交换函数返回，就自动拉高 CS。

## 8. LIS3DH 单寄存器协议

本例四线 SPI 命令字节为：

```text
bit7      bit6       bit5 … bit0
R/W       MS         寄存器地址
1=读      1=递增
0=写      0=不递增
```

WHO_AM_I 地址 `0x0F`，只读，预期值 `0x33`。单寄存器读命令为：

```text
0000 1111  地址 0x0F
1000 0000  读取标志 0x80
1000 1111  读取命令 0x8F
```

同一次 CS 低期间：

```c
(void)SPI_Exchange8(0x8F);          // 命令阶段返回值不用，但已读 DR
uint8_t id = SPI_Exchange8(0x00);   // 数据阶段得到 0x33 才符合 ID 预期
```

这只是命令与数据片段，外面仍需 CS 和最后的结束确认。没有实际读到过 ID，不将预期值写成测量结果。

写入某个允许写的寄存器时，第二次发送实际数据，例如 `0x57`。它是写入数据，不是新的命令。WHO_AM_I 本身只读，不拿它作为写入示例。具体目标寄存器和配置位须另查手册。

## 9. 连续读取：一次命令，多个数据字节

从 `0x28` 开始读取并使地址递增：

```text
0010 1000  起始地址 0x28
1100 0000  读＋递增 0xC0
1110 1000  命令 0xE8
```

`0xA8` 只有读取位，没有递增位；本例连续数据访问时地址将保持起始地址，不能期待得到六个连续寄存器。

以下代码片段演示保存六个原始字节，未包含初始化、超时、器件配置及具体 CS 延时实现：

```c
uint8_t data[6];

CS_Low();
(void)SPI_Exchange8(0xE8);

for (uint8_t i = 0; i < 6; i++)
{
    data[i] = SPI_Exchange8(0x00);
}

while ((SPI1->SR & SPI_SR_TXE) == 0) {}
while ((SPI1->SR & SPI_SR_BSY) != 0) {}
// 满足器件 CS 保持时序后执行：
CS_High();
```

```text
交换次数：  1       2       3       4       5       6       7
MOSI：     0xE8    占位    占位    占位    占位    占位    占位
读取地址：  —      0x28    0x29    0x2A    0x2B    0x2C    0x2D
保存位置： 丢弃    data[0] data[1] data[2] data[3] data[4] data[5]
```

传感器递增寄存器地址，CPU 递增数组下标。第一个占位交换已经接回第一个数据字节，不再额外加一次。六个数据字节共七次交换；若题目改为六个测量值、每值两字节，则为十三次交换。

命令包含地址，不再额外发送独立地址字节。CS 持续低的数据阶段重复发 `0xE8`，不会自动重新解析为新的命令，会额外推动一次数据交换。该协议规则属于 LIS3DH，不能直接套用其他器件。

本轮没有展开六字节到三轴测量值的字节序、有效位、符号与量程换算，也未核对运行配置和数据一致性设置。

## 10. 读出数据后的软件存储

读 DR 后，程序需要把返回值保存到变量或数组，SPI 硬件不会自动修改普通变量。本轮不使用 DMA。

```c
uint8_t ReadExample(void)
{
    uint8_t data = 0x33;
    return data;
}

// 调用方：
uint8_t id = ReadExample();
```

返回的是数值。内部 data 生命周期结束，不会消除调用方 id 已保存的值；id 在自己的生命周期内保留该值，直至程序修改它等情况。普通局部变量不等于堆分配，编译器可能使用通用寄存器或栈。

两次交换只有赋值给同一变量才构成覆盖；哪次返回目标数据由传感器协议决定，不由变量覆盖决定。

## 11. 初始化条件：本轮为概览

| 配置 | 本例要求 |
| --- | --- |
| 时钟 | 开启对应 GPIO、SPI；使用重映射时还需相应 AFIO 配置 |
| SCK/MOSI | F103 复用推挽输出 |
| MISO | 输入，例如浮空输入 |
| CS | GPIO 推挽输出，通信前保持高 |
| 角色与方向 | 主机、双线全双工 |
| 帧格式 | 8 位、高位先行 |
| 时钟模式 | LIS3DH 本例按其空闲高、上升沿采样时序使用模式 3：CPOL=1、CPHA=1 |
| 软件 NSS | SSM=1、SSI=1；内部 NSS 管理不代替外部 GPIO CS |
| 速度 | 用分频满足器件最高频率及其他时序限制 |
| 使能 | 完成配置后开启 SPI |

F103 的 SPI1 位于 APB2，示例计算：

```text
假设 APB2 = 72 MHz
SCK = 72 MHz / SPI 分频系数
4 分频 → 18 MHz，超过 LIS3DH 10 MHz 上限
8 分频 → 9 MHz，满足该频率上限
```

APB2=72 MHz 是题设，不代表已经读取或验证实际时钟树；SPI 分频不使用定时器时钟倍频规则。9 MHz 仍需满足器件其余时序、电平与实际连线条件。
